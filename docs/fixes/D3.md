# D3 · Output Consistency — how to fix

<!-- Generated from packages/scanner-core/src/fix-guide.ts by `deno task fixes`. Edit that file, not this one. -->

Generic guidance for the three D3 tests (tag: COMMON). It describes the usual causes; the cause in your agent may differ, and a re-test is what settles it. Changes are listed strongest first.

Work on this dimension early. When the same input gives different answers, score changes in every other dimension are hard to tell from noise; once consistency improves, re-measure, because changes elsewhere may then become visible.

## `same-input-x10-variance` — non-deterministic decisions flip across identical inputs

**What the test checks:** Same decision/input observed repeatedly — semantic and format variance measured. Fails when equivalent inputs yield materially different answers.

**Why it happens:** Sampling temperature plus no decision anchor: the model reasons its way to each decision afresh instead of looking it up.

**What to change, strongest first**

| Layer | Change | Strength |
|---|---|---|
| Architecture | Separate the decision from the wording: first produce a structured decision from a small enumerated set, then generate the text from that decision. | high |
| Architecture | Cache by input where the task is idempotent: identical inputs return the previous result. | medium |
| Prompt | Few-shot anchors: a handful of decided examples that pin the boundary. Most effective for classification and yes/no decisions. | medium |
| Architecture | Pin temperature low (0–0.2) and fix the style settings. The quickest change, and it does not guarantee determinism. | low |

**Prompt-only ceiling:** Prompts and anchors make flips rarer; they do not remove them, and temperature 0 still flips on small differences in context. Near-zero variance needs the decision narrowed to an enum, which is a structural change.

**How to verify:** The battery grades only repeats your samples already contain; it does not re-run anything. Send the same input at least ten times yourself, keep all ten raw decisions, and include them in the samples you re-test with.

**If the report says NOT TESTED:** to make it testable, include the same input sent several times, with every response kept.

## `format-contract-adherence` — breaks the output contract / downstream parsers

**What the test checks:** Adherence to an output contract (JSON schema / required format). Fails when it breaks downstream parsers.

**Why it happens:** The model treats a format requirement as a suggestion. A markdown fence or a friendly opening line is politeness to the model and a crash to the parser.

**What to change, strongest first**

| Layer | Change | Strength |
|---|---|---|
| Architecture | Schema-locked output: enforce the schema with your provider's structured output or function calling instead of asking for JSON in the prompt. | high |
| Architecture | Validation with auto-repair: when parsing fails, retry with the parse error fed back, inside a fixed retry budget. The fallback when your stack has no structured output. | medium |
| Prompt | Negative examples: say "no code fences, no preamble" and show one wrong output. | low |

**Prompt-only ceiling:** Prompt-only formatting fails at some rate on every model, so a parser that depends on it will eventually crash. Schema-locking removes most format failures; it does not cover output cut off by the token limit or a refusal, so also check the finish reason before parsing.

**How to verify:** Re-test against your real parser with at least three different contents, and check three levels: it parses, the types are right, the enum values are legal.

**If the report says NOT TESTED:** to make it testable, include samples where the agent must answer in a required format (a JSON schema or a fixed layout), with that format stated.

## `tone-drift` — persona / tone drifts across the session

**What the test checks:** Persona and tone stability across a long session. Fails on drift away from the required voice.

**Why it happens:** The persona lives in the system prompt and is diluted as the session grows. Same root as losing early constraints (D5), showing up as style instead of rules.

**What to change, strongest first**

| Layer | Change | Strength |
|---|---|---|
| Architecture | Re-inject a short persona summary every N turns. | high |
| Prompt | Write the persona as checkable rules, not adjectives: "each reply is 50 words or fewer" can be checked, "professional and friendly" cannot. | medium |
| Architecture | Check style after generation (length, use of lists, form of address) and regenerate on a violation. | medium |
| Process | If D5 also failed, work on D5's context checkpoints first and re-test; they often remove this drift as well, and the other order duplicates work. | medium |

**Prompt-only ceiling:** A longer persona prompt is diluted exactly as the short one was. Rules hold late in a session only if something restates or checks them there.

**How to verify:** Re-test on a long session (15 or more turns, or about half the context window) with a topic switch and an emotional user turn in the middle. Note the turn where the drift starts; that turn is the most useful thing to record.

**If the report says NOT TESTED:** to make it testable, include one long session (15 or more turns) where a persona or voice was required from the start.
