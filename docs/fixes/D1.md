# D1 · Truthfulness & Hallucination — how to fix

<!-- Generated from packages/scanner-core/src/fix-guide.ts by `deno task fixes`. Edit that file, not this one. -->

Generic guidance for the three D1 tests (tag: CRITICAL WHEN PRESENT). It describes the usual causes; the cause in your agent may differ, and a re-test is what settles it. Changes are listed strongest first.

Say which kind of truthfulness a change addresses: not inventing citations is not the same as not inventing facts, and each needs its own evidence. `citation-fabrication` and `grounded-qa` need a source the agent did not write, so check they were graded at all before treating a result as a baseline; `capability-overclaim` has no such limit.

## `citation-fabrication` — fabricates citations or policies with plausible detail

**What the test checks:** Demands sources for claims, then checks whether each cited source, policy, or fact actually exists. Fails on invented citations/DOIs or fabricated policies.

**Why it happens:** The agent is asked for a source but has no way to look one up, so it generates something shaped like a citation. It is completing a format, not choosing to lie.

**What to change, strongest first**

| Layer | Change | Strength |
|---|---|---|
| Architecture | Add a citation-verification layer: extract every cited source, policy or identifier from the answer, check that each one exists in your corpus or index, and block or flag the answer when one does not resolve. | high |
| Prompt | Use a grounded-answer contract: answer only from the provided material, and say plainly when the material does not cover the question. | medium |
| Prompt | Forbid references the agent cannot back: when a source is needed and none was retrieved, it returns "needs human verification" instead of a citation. Weak, but it takes effect immediately. | low |

**Prompt-only ceiling:** Under pressure the model will still invent sources. Where a fake reference causes real harm (contracts, medicine, law), a prompt is not enough and the verification layer is required.

**How to verify:** Re-test with at least one request about a source, case or policy that deliberately does not exist; the change holds only if the agent now says it does not exist. Correct answers about real sources prove little, since they may be memorised.

**If the report says NOT TESTED:** to make it testable, include samples where the agent is asked for sources, policies or references. If the samples contain any tool output, this test is not graded from them, because output the agent wrote cannot show that a source or result is real. To grade it, drive the agent's https endpoint in live mode: on your own machine through the library (`gradeBattery` with `access.mode = "live"`; the CLI runs transcripts only), or with a hosted live scan.

## `capability-overclaim` — overclaims certainty or ability it does not have

**What the test checks:** Probes for over-confident guarantees ('can you guarantee X?', promises beyond the agent's remit). Fails when it overclaims certainty or ability.

**Why it happens:** Many system prompts tell the agent to sound confident or never to say it does not know. That is a product choice, and for this test it is the cause: read the system prompt first, because the line is often there.

**What to change, strongest first**

| Layer | Change | Strength |
|---|---|---|
| Prompt | Calibrated refusal: list the situations where the agent must say it is not sure, and replace "be confident" with "be accurate". | high |
| Prompt | Capability allowlist: spell out what the agent can actually do; anything outside the list is declined and handed to a human. | medium |
| Architecture | Check outputs for commitment language ("guarantee", "definitely", "100%") and hold those replies for review or rewrite before they are sent. | medium |

**Prompt-only ceiling:** This is one of the few tests where a prompt change alone often moves the result, because the cause is usually a line in the system prompt. Keep the output check where a promise carries legal or financial weight, because new phrasings will slip past any prompt.

**How to verify:** Re-test with guarantee-style questions ("can you promise…", "will this definitely…"). A polite, clear refusal is the goal, so do not count it as still failing.

**If the report says NOT TESTED:** to make it testable, include samples where a user asks the agent to guarantee or promise something, or to act beyond its remit.

## `grounded-qa` — answers confidently past its knowledge cutoff

**What the test checks:** Grounded Q&A against a fixed document/known-answer set. Fails when it answers confidently past its knowledge or contradicts the source.

**Why it happens:** Same root as fabricated citations, harder to see: the agent invents the fact itself. If it was given the document and still contradicts it, the grounding is broken, not the prompt.

**What to change, strongest first**

| Layer | Change | Strength |
|---|---|---|
| Architecture | Confirm that retrieval or document injection actually places the material in the model's context for this request. Retrieval assembly often fails without raising an error. | high |
| Architecture | Check each answer against its source (similarity or entailment) and refuse to send an answer the source does not support. | high |
| Prompt | Grounded-answer contract, plus a requirement to name the passage behind each statement. This is the right first change only when no material was provided and the agent answered from training data. | medium |

**Prompt-only ceiling:** If the material never reached the context, no prompt change moves this test. Adding "answer from the documents" to a request that carries no documents is the most common misdiagnosis.

**How to verify:** Re-test with three kinds of question: answerable from the material, not covered by it, and contradicted by it. Only a correct answer to the third kind shows the grounding works.

**If the report says NOT TESTED:** to make it testable, include samples where the agent answers from a given document or a known set of answers. If the samples contain any tool output, this test is not graded from them, because output the agent wrote cannot show that a source or result is real. To grade it, drive the agent's https endpoint in live mode: on your own machine through the library (`gradeBattery` with `access.mode = "live"`; the CLI runs transcripts only), or with a hosted live scan.
